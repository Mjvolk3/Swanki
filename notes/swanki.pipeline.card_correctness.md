## 2026.06.01 - Initial implementation

Opt-in correctness gate addressing the "faithful but wrong" failure: a card can be a perfect transcription of the source and still teach a falsehood. The anchor case is an Alcamo Schaum's Microbiology CH02 multiple-choice card ("A hydrogen bond is a weak bond forming between (a) three pairs of electrons ... (d) protons and three pairs of electrons") that is verbatim from the textbook yet chemically nonsensical. Plan: [[plan.post-creation-llm-card-correctness-gate.2026.06.01]].

**Entry point.** `run_correctness_gate(cards, doc_summary, source_context, model_string, *, max_workers=8) -> (kept_cards, audit)`. Each card is assessed independently and concurrently (`ThreadPoolExecutor`, mirroring `markdown_converter`). `card_correctness_agent` (in [[swanki.llm.agents]]) returns a `CardCorrectnessAssessment` with `verdict ∈ {pass, fixed, dropped}` plus a reason and, for `fixed`, corrected front/back. Every call is wrapped in `with_safety_retry` ([[swanki.llm.safety]]) because microbiology content reliably trips the biosec `invalid_prompt` refusal.

**Verdict resolution.** `pass` keeps the card unchanged; `fixed` keeps a `model_copy` with corrected `front`/`back` text; `dropped` excludes the card (quarantine-from-deck — it never reaches markdown/.apkg but its full original content is logged); `assessment_failed` keeps the card fail-open. `assessment_failed` is assigned by the gate when `_assess_card` returns `None` (the call raised after retries) — the agent never returns it. We never silently drop an unjudged card; precedent is the per-segment skip-on-exhausted-retry (commit `14fbfab`).

**Why a single late stage at the `generate_outputs` chokepoint.** All three card-producing branches (`solution_manual`, `glossary`, `full`) funnel into `Pipeline.generate_outputs`. Gating once there (via `_apply_correctness_gate`, before any markdown/.apkg is written) covers every mode with one integration point and keeps the position-keyed sibling artifacts (`cards-plain.md`, etc.) consistent because they are all written from the post-gate kept-list. Wiring into each upstream branch was rejected: two of the three are in-flux and it triples merge surface for no gain.

**Source context is required.** Card text alone cannot separate "faithful but wrong" from correct, so the gate reads the cleaned source (`clean-md-singles/*.md`, joined by `Pipeline._read_source_context`) plus the `DocumentSummary`. The prompt instructs the model to judge against established reality, not fidelity to the source.

**Model + config.** Reuses `get_model_string(models.llm)` by default (`gpt-5.5`); a nullable `card_correctness_gate.model` override pins a stronger model even if a run downgrades the main model for cost. Hydra group `swanki/conf/card_correctness_gate/`, `enabled: false` by default (one model call per card; opt in per run with `card_correctness_gate.enabled=true`).

**Audit.** `write_audit` dumps a `summary` count block plus one `CardAuditEntry` per card to `<output_base>/correctness-assessment.yaml`, atomically (temp-then-rename). Sibling to `provenance.yaml`; never written into the Anki `Feedback` field or `PlainCard.user_feedback` (those are the review-time human-triage channel and part of the GUID seed). Fixing pre-export is GUID-safe — a corrected card gets its natural GUID in a fresh deck with no review history to lose; holding a GUID stable across a fix is the paused unify-regen problem and is out of scope.

**Calibration — factual-only, high acceptance (2026.06.01 user feedback).** The gate is a factual-error catcher, not a quality/style screen. `GATE_INSTRUCTIONS` biases hard toward `pass`: `fixed`/`dropped` are reserved for unambiguous, high-confidence factual errors with an obvious correction (or no recoverable one); style, tone, terseness, phrasing, difficulty, and pedagogical choices are explicitly out of bounds; when in any doubt, pass. The user's stance: the sources are trusted, so we would rather let a few wrong cards slip through than screen off good ones — acceptance must be very high. This calibration lives entirely in the prompt (the structured verdict is unchanged). The complementary lever is the opt-in default: stylistic/essayistic sources like Hamming simply leave the gate disabled, while factual textbooks (Schaum's/Alcamo) enable it per run.

**Default-on + rejection report (2026.06.01 user feedback, second pass).** The user wants the gate ON for all future runs, with rejected cards and their reasons logged so a "why were cards rejected" report can be produced. `card_correctness_gate.enabled` now defaults to `true` (still overridable per run with `enabled=false`); `audio_only` mode is unaffected since it never calls `generate_outputs`, and `_apply_correctness_gate` early-returns when there are no cards so no empty audit is written. Rejection logging is now twofold: `correctness-assessment.yaml` records every card with `verdict`, `reason`, and full `original_front`/`original_back` (so dropped cards carry both the reason and the text needed for a report), and `run_correctness_gate` additionally emits a per-card WARNING for each dropped card (and INFO for each fixed card) so rejections surface in the run log immediately. A cross-deck aggregator over the per-run YAMLs is a possible follow-up, not yet built.

Tests in `tests/test_card_correctness.py` monkeypatch `_assess_card` per card (no live LLM) to cover pass/fixed/dropped/assessment_failed, audit completeness, input-order preservation under concurrency, empty input, all-dropped, and atomic audit write.

## 2026.06.01 - Audit format switched YAML -> JSON

The audit is `correctness-assessment.json`, not `.yaml` (earlier sections above reference the old name). Reason: the user codified a project convention -- YAML for hand-edited config, JSON for emitted machine output -- and the audit is emitted output, not config. `write_audit` now uses `json.dump(payload, f, indent=2, ensure_ascii=False)` (the `ensure_ascii=False` keeps card prose and em-dashes readable). Same atomic temp-then-rename. This also drops the `import yaml` mypy `import-untyped` error. The convention is recorded in CLAUDE.md; the existing pipeline YAML artifacts (`problem-pairings.yaml`, `section-classification.yaml`, `cards-debug.yaml`, `provenance.yaml`) are pre-existing emitted output that technically falls under the new rule but is left for a separate, dedicated migration to avoid colliding with concurrent worktree work.

## 2026.08.16 - Judge each card against its originating excerpt, not the chapter

The gate sent the **whole cleaned chapter with every card**. Measured on `alcamo CH01`: 46 gate calls x 8,179 input tokens = 376,230 input tokens carrying ~13,600 tokens of unique information -- 28x amplification, 99.2% of each call re-sent chapter text against a ~120-token card. That made the gate 25-53% of a run's LLM cost and ~75% of the remaining regeneration campaign.

**Caching cannot fix this, and that was tested rather than assumed.** Four controlled experiments (2026.08.14) established that a prompt-cache hit requires a **byte-identical prompt**, not a shared prefix: 3/4 hits on identical prompts, **0/4** when the ~8.6k prefix matched but the trailing card varied, and `prompt_cache_key` changed nothing (0/6). The card sits in the prompt tail, so every gate call differs by construction. The only lever is to send less.

**The evidence was already computed and thrown away.** Card generation builds a windowed `combined_content` per segment (focal plus `context_radius` neighbours) and that window -- not the chapter -- is literally what the card writer saw. `run_correctness_gate` now takes a keyword-only `card_evidence: dict[str, str]` keyed by `card_id` and resolves per card on the submitting thread: `evidence.get(card_id) or source_context`. `source_context` keeps its positional slot and becomes the whole-chapter fallback, so an empty map is byte-identical to the old behaviour and every existing call site still type-checks.

**Verbatim reuse, deliberately not narrower.** Corpus-wide over 228 segmented output dirs / 1906 segments: whole chapter 151.8M chars; radius-2 window **43.1M = 71.6% saving**; radius 1 27.7M = 81.7%; focal-only 9.9M = 93.5%. Focal-only was rejected despite being the cheapest. Reusing exactly what the writer saw makes the change *evidentiary-neutral by construction*; narrow further and an unsupported card is ambiguous between "this is wrong" and "you cropped the proof". `CardCorrectnessAssessment.verdict` is `Literal["pass","fixed","dropped"]` -- there is no "cannot verify" -- so that ambiguity would resolve as screening, which is exactly what the gate's very-high-acceptance calibration forbids.

**The prompt relabel is calibration protection, not cosmetics.** `SOURCE TEXT` became `ORIGINATING EXCERPT` in both `GATE_INSTRUCTIONS` and `_build_prompt`, with an explicit instruction that the excerpt is not the whole document and that **absence of supporting text in it is never grounds for `fixed` or `dropped`** -- judge only what the excerpt positively contradicts. Without this, a card whose supporting fact sits just outside the window could read as "the prompt's premise is false" and be dropped, which is a hard delete from deck, `.apkg`, and audio. The historical baseline across 85 audits / 3599 cards is 98.36% pass, 1.56% fixed, 0.08% assessment_failed and **zero dropped, ever**; a first-ever drop is the over-screening signal.

**This restores documented intent.** [[plan.post-creation-llm-card-correctness-gate.2026.06.01]] decision 4 specified that the gate receives "the originating source segment text plus the DocumentSummary". The whole-chapter behaviour was a shipped deviation, and the "Source context is required" paragraph above plus the module docstring had been describing that deviation as though it were the design. Both are now corrected; treat this section, not that paragraph, as current.

Unchanged: the verdict enum, fail-open on `_assess_card` returning `None`, one audit entry per input card in input order, the `generate_outputs` chokepoint, the audit format, and the config surface -- deliberately **no** new Hydra key, since the per-card fallback and `git revert` are already two escape hatches and a `use_segment_context` boolean would be flipped once and then live forever as dead config.
